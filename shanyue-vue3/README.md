# 山月茶咖 SHANYUE TEA & COFFEE ☕🍵

> 「山月入杯，茶咖相宜」—— 基于苍穹外卖（sky-take-out）架构改造的**茶饮自取点单系统**，双端 Vue3：商家管理后台 + 顾客 H5 点单。

## 项目简介

| | |
|---|---|
| 业务 | 顾客在 H5 浏览菜单 → 选规格（杯型/温度/糖度/浓度）→ 加购 → 下单拿到**取餐号（A01）** → 到店取餐；商家在管理后台接单 → 制作 → 出餐叫号 |
| 双端 | **admin**：Vue3 + Vite + Element Plus 管理后台（5173）；**h5**：Vue3 + Vite + Vant 4 移动端点单（5174） |
| 后端 | Spring Boot + MyBatis + MySQL + Redis（入门）+ WebSocket，由你在原苍穹外卖工程上按《开发指引》改造实现 |
| 前端形态 | **开箱即用**：内置完整 mock（数据存 localStorage，刷新不丢），后端未完成时即可完整演示全部交互 |

核心学习点：结构化规格树建模与动态算价、多表事务与"先删后插"整体覆盖、订单状态机、Redis 按天自增取餐号、缓存一致性与防穿透、WebSocket 实时提醒、延迟消息超时取消。

## 快速开始

> 环境：Node 18+。两个前端均可独立运行，**mock 开箱即用，无需后端**。

```bash
# 1. 管理后台（端口 5173）
cd admin && npm i && npm run dev

# 2. H5 点单（端口 5174，另开一个终端）
cd h5 && npm i && npm run dev
```

- mock 默认开启（`VITE_USE_MOCK=true`），内置 5 分类 / 13 商品 / 43 规格组 / 122 规格选项，以及 3 条不同状态订单；数据持久化在 localStorage，「重置演示数据」按钮可恢复出厂（admin 在头像菜单，h5 在取餐查询页）。
- 演示账号：`admin / 123456`（教师演示账号）。
- **仪表盘待办提醒（admin）**：待接单积压（含最早一单已等待分钟数）、券库存告急（剩余 < 20%）、停售中饮品数、店铺打烊状态四类待办，点击直达对应页面处理；全部清零时显示「井然有序」。
- **来单提醒模拟（admin，mock 专属）**：顶栏「🔔 来单提醒」开关，开启后每约 45 秒模拟一个顾客下单——右上角弹出通知（取餐号/金额/品项）+ 提示音（Web Audio 合成，无外部资源）+ 订单页数据自动刷新。这对应真实后端阶段 7 的 WebSocket `NEW_ORDER` 推送：接入真实后端后，此开关自动消失，由服务端推送取代。
- **演示推进（h5，mock 专属）**：取餐查询页对状态 1/2/3 的订单显示「⏩ 演示推进」按钮，单人即可模拟商家接单→出餐→取餐，把订单沿真实状态机推进一步；对接真实后端后按钮自动隐藏。
- **会员中心 + 优惠券（h5）**：首页顶栏「会员·领券 ›」或点击公告栏「🎫 N 张券可领」进入会员中心——会员卡（积分余额 / 累计消费 / 可用券数）、领券广场（每张限领 1 张、库存随领取递减）、我的优惠券（可用/历史核销）；确认下单页「优惠券」行选券抵扣，实付 = 商品总额 - 券面额，下单成功后同事务核销（历史券带核销订单号）。对应后端扩展任务卡 T9（api-docs 模块 13，5 个接口）。
- **优惠券管理（admin）**：侧边栏「优惠券管理」——券模板分页查询/新增/编辑（满减券与无门槛券，门槛低于面额等非法配置会被前后端双重拦截）、上/下架开关（下架后 C 端券广场不可见，已领取的券仍可用）、删除（已有用户领取时禁删）、发放进度条与累计领取统计。对应 api-docs 模块 14（5 个接口），与 h5 领券/核销同属扩展任务卡 T9。
- **积分体系（h5）**：会员中心新增每日签到（本周日历格子 + 连签天数 🔥，每日 +7 分）、积分兑换（按券面额定价 1 积分 ≈ 0.1 元，余额不足按钮置灰提示「差 N 分」）、积分明细时间线（签到/订单消费/兑换三类流水，倒序展开收起）；下单成功页显示「完成后可得 N 积分」。积分余额与会员卡/会员概要同源，与优惠券构成「签到攒分 → 兑券 → 下单核销」营销闭环。对应后端扩展任务卡 T10（api-docs 模块 15，5 个接口）。
- **连续签到奖励（h5，v1.5）**：签到卡新增连签进度条（7 格，按 streak % 7 点亮，终点 🎁）；每连续签到 7 天额外 +20 积分，达成瞬间播放全屏彩带雨 + 中央徽章庆祝动效（接口返回 justBonus 驱动）；签到按钮在「今天签到将达成」时预提示可得 +27；mock 下提供「⏩ 演示：补签 6 天」按钮，一键注入历史后点签到即可复现达成场景。对应 api-docs 15.1/15.2（v1.5 新增字段）。
- **商品搜索（h5，v1.5）**：点单首页门店条下方新增搜索框，支持按商品名 / 描述 / 分类名模糊匹配（如「拿铁」「可颂」「茶饮」）；搜索态下隐藏招牌横滑与分类侧栏，平铺展示结果并计数，支持一键清空退出；空结果显示空态引导。接口仍复用 8.2 菜单列表（前端本地过滤；真实后端数据量大时可升级 8.2 的 name 模糊查询）。
- **再来一单（h5，v1.5）**：取餐查询页对已完成/已取消订单显示「🛒 再来一单」按钮——按原规格（specKey 反查）逐件重新加入购物车（复用 8.4 接口，服务端重算金额、同规格合并），全部成功跳回首页直接结算；部分品项已停售时跳过并提示哪些未加入。
- **券库存补量（admin，v1.5）**：优惠券管理页操作列新增「补量」快捷操作（已下架券置灰）——弹窗显示当前已领/总量，快捷 +50/+100/+200/+500 chips + 自定义数量，实时预览补后总量与剩余可领；复用 14.3 修改接口只改 totalCount（服务端校验 ≥ 已领取）。
- **订单小票打印（admin）**：订单页每行新增「小票」按钮，弹出 58mm 热敏小票样式预览（店铺名/取餐号大字/等宽字体明细/优惠与实付/订单号条形码装饰/slogan），点「打印小票」调起浏览器打印（打印态只输出小票本体）。真实门店可对接热敏打印机（如 ESC/POS 指令集或云打印接口）。
- **领券告急提醒（admin）**：仪表盘待办提醒新增一类——发放中且剩余 < 20% 的券自动出现在待办列表（按告急程度排序，展示剩余张数占比），点击直达优惠券管理页补量或下架；与来单模拟联动实时刷新。
- **门店信息页（h5，v1.6）**：首页门店头品牌行/「门店信息 ›」进入——门店头卡（banner + 实时营业状态 + 评分）、山月的品牌故事、门店信息（营业时间/地址/一键拨号/公告）、评价总览（平均分大字 + 星级分布条 + 标签热度）、评价墙（取餐号徽标 + 星级 + 内容 + 商家回复卡，可展开全部）。
- **评价体系（h5 + admin，v1.6）**：C 端取餐查询页对已完成订单显示「⭐ 评价」——底部弹层星级（1~5 星大按钮 + 感性文案）+ 标签快选（口味赞/出餐快/服务贴心等 6 项多选）+ 文字评价（50 字计数），一单一评，提交后变「已评价 ★ 5.0」徽标；首页门店头实时显示门店评分；会员中心新增「我的评价」（含商家回复，可展开）。管理端新增「评价管理」页——口碑总览（平均分/评价数/好评率/待回复）+ 星级分布 + 标签热度 + 评价列表（星级筛选/关键词搜索/隐藏态筛选），商家可回复评价（一评一回复，可改）与隐藏/恢复不当内容（删除线 + 统计实时联动）；仪表盘新增「门店口碑」卡直达。对应后端扩展任务卡 T11（api-docs 模块 16/17，8 个接口）。

## 对接自己的后端（三步）

后端由你参照苍穹外卖工程改造（Java 侧工程不在本仓库，见开发指引）：

1. **照 `docs/dev-guide.md` 分阶段开发后端**：从工程改名、建库 `shanyue_tea` 开始，8 个阶段每阶段都有「动手任务清单 + 验收标准（用本仓库前端联调）」，建议完成一个阶段联调一个阶段。
2. **关掉 mock**：把 `admin/.env.development` 和 `h5/.env.development` 里的 `VITE_USE_MOCK` 改为 `false`，重启 dev server（改 .env 必须重启）。
3. **proxy 不用改**：两个工程的 `vite.config.ts` 已把 `/admin`、`/user`、`/ws`、`/upload` 等前缀代理到 `http://localhost:8080`，后端跑在 8080 即可，也**无需**在后端配置 CORS。

后端最小可联调顺序：阶段 0-2 完成 → admin 登录/员工/分类/店铺可用；阶段 3 完成 → 饮品管理可用；阶段 4 → 订单管理；阶段 5-6 → h5 点单闭环；阶段 7 → WebSocket 提醒。

## 联调自查清单（简版）

- [ ] `VITE_USE_MOCK=false` 已生效（Network 面板能看到真实请求，而不是 localStorage 瞬返）
- [ ] 后端 8080 已启动，`GET /user/shop/status` Postman 可通
- [ ] admin 能登录，后续每个请求头都带 `token`；401 时先重新登录
- [ ] 金额口径：后端全链路**分**（1590），前端展示 ÷100，两边都别出现 15.9
- [ ] 时间格式：接口返回 `yyyy-MM-dd HH:mm:ss`（后端 JacksonObjectMapper 已改带秒）
- [ ] 分类删除被约束（有饮品禁删，msg「该分类下存在商品，无法删除」）
- [ ] 饮品编辑保存后，规格树回显一致（先删后插生效）；停售饮品不可删除
- [ ] h5 加购：同款同规格合并数量，金额 = 服务端重算值；下单成功购物车清空并返回取餐号
- [ ] 下单后 admin 订单页 tab +1；出餐叫号 / 催单 / 来单三种 WebSocket 消息 admin 能收到
- [ ] 失败场景都有友好 toast：错误密码、非法状态流转（code=0 + 中文 msg）
